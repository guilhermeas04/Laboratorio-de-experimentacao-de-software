# RQ03 e RQ04

Base analisada: 100 repositórios mais populares coletados no GitHub em 12 de
agosto de 2026.

## RQ03 — Sistemas populares lançam releases com frequência?

Resposta direta: parcialmente.

Métrica usada: total de releases informado por `releases.totalCount`.

Resultados principais:

- Total de repositórios analisados: 100
- Mediana: 15 releases
- Média: 133,66 releases
- Primeiro quartil: 0 releases
- Terceiro quartil: 167,25 releases
- Mínimo: 0 releases
- Máximo observado: 1.000 releases
- Repositórios sem releases: 41

| Repositório | Releases | Dias desde a última atualização |
|---|---:|---:|
| langchain-ai/langchain | 1.000 | 0 |
| vercel/next.js | 1.000 | 0 |
| ggml-org/llama.cpp | 1.000 | 0 |
| electron/electron | 1.000 | 0 |
| anomalyco/opencode | 858 | 0 |

Discussão: há grande dispersão. Embora alguns projetos apresentem centenas de
releases, 41% da amostra não possui nenhuma release e pelo menos metade possui
no máximo 15. A média é muito superior à mediana por causa dos projetos com
contagens elevadas. O total acumulado também não mede diretamente a frequência,
pois não considera a idade ou o intervalo entre releases.

Conclusão: não é possível afirmar que todos os sistemas populares lançam
releases com frequência. O comportamento varia bastante e uma parcela relevante
não utiliza releases do GitHub. Em uma etapa posterior, a métrica pode ser
normalizada pela idade do repositório ou pelo tempo entre releases.

## RQ04 — Sistemas populares são atualizados com frequência?

Resposta direta: o resultado observado sugere atualização recente, mas é
inconclusivo.

Métrica usada: dias decorridos desde `updatedAt` até a data da coleta.

Resultados principais:

- Total de repositórios analisados: 100
- Mediana: 0 dias
- Média: 0 dias
- Mínimo: 0 dias
- Máximo: 0 dias
- Atualizados nos últimos 7 dias: 100

Discussão: todos os registros retornaram `updatedAt` no mesmo dia da coleta.
Esse campo representa mudanças gerais no repositório e pode ser alterado por
eventos que não correspondem a novos commits, como atividade em Issues ou Pull
Requests. Por isso, a ausência de variação impede comparar adequadamente a
frequência de atualização do código entre os projetos.

Conclusão: com `updatedAt`, os 100 repositórios parecem recentes, mas a RQ04 não
pode ser respondida com segurança. Recomenda-se acrescentar `pushedAt` nas
próximas coletas para medir a última atualização do conteúdo do repositório.
